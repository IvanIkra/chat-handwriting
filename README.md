# «Это точно Саша?»

Тема хакатона: **«Интернет больше не доказательство»**.

Сообщение в мессенджере больше не доказывает, кто его написал. Аккаунты взламывают, и «друг» пишет «Привет! Срочно займи 5000». Один человек ведёт несколько аккаунтов и поддакивает сам себе. Мы проверяем автора не по аккаунту, а по **почерку**: как человек пишет, какие слова и знаки ставит, когда бывает онлайн.

Работаем с JSON-экспортом Telegram Desktop. Вердикт — всегда вероятность с уликами, а не приговор.

## Что умеет

| Режим | Вопрос | Что видно |
|---|---|---|
| **Паспорт почерка** | Как пишет этот человек? | 5–10 черт («с маленькой буквы — 100%», «скобки вместо эмодзи»), часы активности, любимые слова и эмодзи |
| **Проверка** | Это сообщение точно от Саши? | Оценка 0–1 и вердикт, расхождения подсвечены прямо в тексте. Можно проверить одно сообщение или серию подряд. При сомнении — контрольный вопрос из вашей общей истории |
| **Двойники** | В группе точно разные люди? | Граф участников, пары «скорее всего один человек» с уликами и сообщения обоих аккаунтов рядом |
| **Два чата** | Саша и Alex — один человек? | Каждый автор одного чата против каждого автора другого. Общие участники (обычно вы сами) в сравнение не идут |

## Как это работает

Классическая стилометрия на scikit-learn, без обучения нейросетей:
- **Почерк:** символьные n-граммы, пунктуация, регистр, скобки и эмодзи, длина сообщений, характерные и редкие слова.
- **Время:** часы активности. Двойники никогда не пишут одновременно и переключаются за десятки секунд.
- **Улики:** каждая — место, где текст идёт против привычек автора. Её сила — во сколько раз такое вероятнее у обычного человека, чем у этого автора.
- **Самопроверка:** сообщения каждого автора делятся пополам, и мы смотрим, находят ли половины друг друга. Это наша честная цифра точности.
- **LLM (Claude API), по желанию:** объяснение улик человеческим языком и контрольный вопрос из переписки. Без ключа всё работает, просто без этих текстов.

Данные хранятся только в памяти бэкенда до перезапуска.

## Результаты на демо-данных

Синтетические переписки из [`demo/`](demo/README.md), без LLM:

- **Фейки** от «взломанного» Саши: 8 из 8 получают «не похоже» (0.00–0.17).
- **Настоящие** сообщения Саши: ни одно не получает «не похоже». Три лучших дают 0.61–0.70.
- **Двойники:** Дима и Миша в групповом чате — «скорее всего один человек», 0.91. Следующая пара — 0.33.
- **Два чата:** Саша и Alex — «скорее всего один человек», 0.89.
- **Самопроверка:** 6 из 6 участников группы нашли сами себя.

## Запуск

Нужны Python 3 и Node.js. Каждую команду запускайте из корня репозитория.

```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cd frontend && npm install
```

Бэкенд (порт 8000) и фронтенд (порт 5173, проксирует `/api` на бэкенд):

```bash
cd backend && .venv/bin/uvicorn app.main:app --reload --port 8000
cd frontend && npm run dev
```

Откройте http://localhost:5173 и загрузите `demo/personal_main.json`. Строки для проверки — в `demo/checks.txt`.

- **Без бэкенда:** `cd frontend && npm run dev:mock` — фронтенд на моках из контракта.
- **С LLM:** `cp .env.example .env` и впишите `ANTHROPIC_API_KEY`.
- **Без LLM при заполненном `.env`:** запускайте бэкенд с пустым ключом: `ANTHROPIC_API_KEY= .venv/bin/uvicorn …`. Команда `env -u` не поможет: ключ всё равно подхватится из `.env`.

Тесты и линт: `cd backend && .venv/bin/pytest && .venv/bin/ruff check .`, `cd frontend && npm test && npm run lint`.
