# Проект: vibehack

Хакатон. Команда из двух человек, оба пишут параллельно через Claude Code на своих машинах.
Цель процесса: не мешать друг другу и всегда иметь рабочий `main`.

## Стек и команды
- Стек: бэкенд — Python 3 + FastAPI (uvicorn, pytest, ruff); фронтенд — React + TypeScript + Vite
- Продукт и MVP — `docs/IDEA.md`. Анализ: scikit-learn (стилометрия); LLM — Claude API, ключ `ANTHROPIC_API_KEY` в `.env`, без ключа всё работает, только без LLM-текстов
- Данные: реальные экспорты Telegram лежат только в `data/` (в `.gitignore`) и не коммитятся; для тестов — маленькие выдуманные фикстуры в `backend/tests/fixtures/`
- Установка зависимостей: `cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`; `cd frontend && npm install`
- Запуск: `cd backend && .venv/bin/uvicorn app.main:app --reload --port 8000`; `cd frontend && npm run dev` (порт 5173)
- Тесты: `cd backend && .venv/bin/pytest`; `cd frontend && npm test`
- Линт/формат: `cd backend && .venv/bin/ruff check . && .venv/bin/ruff format .`; `cd frontend && npm run lint`

Правила:
- Не редактируй файлы чужой зоны. Если там нужно изменение — создай issue с меткой зоны и скажи об этом мне.
- Общие файлы меняются отдельным маленьким PR, который второй человек должен увидеть.

## Контракт
Интерфейс между зонами (API, форматы данных, общие типы) описан в `docs/CONTRACT.md` — это источник истины.
- Сначала меняется контракт (команда `/contract`), потом код с обеих сторон.
- Никогда не меняй формат API или данных молча.
- Пока вторая сторона не готова, работай против мока по примерам из контракта.

## Git
- `main` всегда запускается. Прямых пушей в `main` нет, только PR.
- Одна задача = один issue = одна ветка `<номер-issue>-<коротко>` = один PR.
- Ветки короткие: от 30 минут до пары часов. Синхронизация с `main` — команда `/sync`.
- После rebase пушить только `git push --force-with-lease`, никогда не `--force`.
- Мерж — squash. Свой PR в своей зоне с зелёными проверками можно мержить самому. PR, задевающий общее, мержится после ок от второго.
- Конфликт в lock-файле: не правь руками — возьми версию из `main` и переустанови зависимости.
- Новые зависимости — отдельным коммитом, с упоминанием в описании PR.
- Не упоминай Claude и ИИ-ассистента как автора в коммитах, PR, issues и коде: никаких `Co-Authored-By: Claude`, «Generated with Claude Code» и подобных подписей.

## Задачи
Доска — GitHub Issues с метками `zone:A`, `zone:B`, `shared`.
Взял задачу — назначь себя (`/task`). Закрывается автоматически через `Closes #N` в PR.

## Как работать (для Claude)
- Перед кодом — короткий план, жди подтверждения, если задача больше пары файлов.
- Меняй только то, что нужно для задачи. Никаких массовых рефакторингов, переименований и переформатирования вне задачи — это главный источник конфликтов.
- После изменений запускай тесты и линт.
- Хакатон: работающее важнее идеального, но без захардкоженных секретов.
- Секреты только в `.env` (в `.gitignore`), шаблон — в `.env.example`. Не читай и не выводи `.env`.
- Не делай ничего с удалённым репозиторием (push, PR, merge, issues) без моей команды, кроме шагов внутри `/task`, `/sync`, `/ship`, `/contract`.
